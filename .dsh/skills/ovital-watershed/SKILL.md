# 奥维集水区绘图 Skill（ovital-watershed）

本 Skill 约束模型在“奥维互动地图 + 本地 MCP 服务”环境中完成**地表上游集水区**的判读、计算、复核与落图。GIS 引擎负责确定性的流向/汇流/面积计算；模型负责理解需求、读取现场信息、实际看图复核、指出疑点、组织修订与汇报。

## 0. 适用范围

适用：

- 用户已在奥维中选中或给出坝址/取水口/控制断面（点或标签），要求生成其**上游集水区（汇水区、流域分水岭）闭合范围**；
- 用户提供（或指定）了带坐标系的 DEM 文件（GeoTIFF），并要求计算、复核、写入奥维草稿、量算或导出；
- 对已有候选边界做分段看图复核、局部修订与回读确认。

不适用或必须明确拒绝：

- 把集水区理解为**可见水面、积水范围、行政区、洪水淹没线**——这些都不是本 Skill 的输出；
- 没有 DEM 仍要求“工程级”自然分水岭边界、或要求保证米级/亚米级精度；
- 要求“按目标面积凑边界”“优化到和参考面积一致”；
- 要求模型凭空写出整圈经纬度顶点（应先算候选，再按分段/锚点修订）；
- 依赖 `deepseek-v4-pro` 看图（该模型不支持图片输入；看图复核须用支持视觉的模型，如 `deepseek-flash`）。

关键判据（任何一步都不放松）：

1. **集水区是地形上游汇水范围**：分水岭沿山脊、山峰、鞍部走，闭合边在出口处跨越河道。它不是影像上最显眼的边界，也不是面积相近的任意多边形。
2. **面积接近不能证明边界正确**；坐标小数位多、奥维写入成功、地面看起来顺滑也都不能单独证明精度。
3. **地形分水岭 ≠ 工程汇水范围**：地下水、岩溶、跨流域引水、人工排水/涵洞、水库调度等会改变实际汇水；这些只能作为项目条件记录并标注，不能靠影像自动推定。

## 1. 工具（MCP serverName = ovital）

所有工具均在 `mcp__ovital__` 命名空间下，共 18 个（`docs/architecture.md` §6 契约表 17 个 + `list_jobs` 辅助工具）。返回统一含 `status`（`ok|error`）、`warnings`、`provenance`；`provenance.verified_against_real_device` 为 `false` 时**不得**说成真实联机验证。

| 工具 | 用途 | 关键输入 | 关键输出 |
|---|---|---|---|
| `mcp__ovital__get_capabilities` | 读能力：版本、连接状态、权限、命令支持矩阵、模拟标志、未验证清单 | — | `version`、`connected`、`permissions`、`simulated`、`verified_against_real_device`、`unverified[]` |
| `mcp__ovital__get_selection` | 读当前奥维选中对象 | `flag`、`latlng_type` | 对象列表（ID/类型/名称） |
| `mcp__ovital__read_object` | 读对象详情（顶点坐标、名称、备注） | `obj_id` | 顶点 EPSG:4490 `(lon,lat)`、语义、原始字段摘要 |
| `mcp__ovital__get_scene` | 取奥维地图图片并附元数据（需 SVIP） | `bbox_lonlat`、`max_level`、`max_pixel` | MCP Image + 范围/CRS 元数据 |
| `mcp__ovital__inspect_dem` | 检查 DEM 质量与覆盖 | `dem_path` | CRS、分辨率、NoData、量程、覆盖范围、高程基准提示、warnings |
| `mcp__ovital__start_watershed` | 起计算任务（持久任务） | `dem_path`、`outlet_lonlat` 或 `outlet_obj_id`、`engine`/`snap_radius_m`/`simplify_tolerance_m` 等参数、`idempotency_key?` | `job_id`（立即返回） |
| `mcp__ovital__get_job` | 查任务状态/阶段/进度/成果；可含复核图 | `job_id`、`include_images` | 状态、阶段、错误、成果摘要；`include_images=true` 时最多 2 张 MCP Image，`review_figure_count` 给出总数 |
| `mcp__ovital__cancel_job` | 取消任务 | `job_id` | 取消结果 |
| `mcp__ovital__list_jobs` | 最近任务列表（辅助恢复上下文） | `limit?`（默认 20，1–100） | `job_id`/状态/进度/创建时间 |
| `mcp__ovital__review_segment` | 分段局部复核图与统计 | `job_id`、`segment_id?`（默认第 1 段）、`max_pixels?` | 该段 MCP Image + 段统计/锚点 ID + `all_segments` + 复核要点 |
| `mcp__ovital__revise_candidate` | 基于已有任务发起修订（重新计算，保留父任务成果） | `job_id`，可选 `outlet_lonlat`/`snap_radius_m`/`min_accum_cells`/`simplify_tolerance_m`/`engine`/`metric_crs`/`anchors_lonlat`/`reason` | 新 `job_id`、前后面积与影响范围；**v0.1 的 `anchors_lonlat` 只记录锚点并重算参数，不会强行把边界拉过锚点**；不支持 `segment_ids`/`constraints` |
| `mcp__ovital__validate_geometry` | 几何拓扑检查 | `geojson` 或 `job_id`、`simplify_tolerance_m?` | 闭合/自交/重复点/细长片/多部件/洞 |
| `mcp__ovital__measure_geometry` | 量算水平面积/周长 | `geojson`/`job_id`、`metric_crs?` | 面积（m²）、周长、顶点数、方法/CRS/单位 |
| `mcp__ovital__write_draft` | 写奥维草稿文件夹（写前快照、幂等、写后回读） | `job_id`/`geojson`、`draft_folder?`、`name?`、`comment?`、`parent_folder_id?`、`idempotency_key?`、`expected_area_m2?` | `obj_id`、回读顶点差异、快照/变更 ID；**v0.1 只支持单一无洞多边形，多部件/孔洞会显式报错**；幂等键可自动派生 |
| `mcp__ovital__read_back` | 从奥维回读对象与量算对比 | `obj_id`、`job_id?`、`expected_area_m2?` | 回读坐标/20802 量算/与本地差异 |
| `mcp__ovital__finalize_draft` | 标记正式成果 | `obj_id`、`confirm=true`、`new_name?`、`comment?`、`version_note?` | 版本记录、`change_id`/`snapshot_id`；20112 替换语义**未在真实设备验证**，写前自动快照 |
| `mcp__ovital__rollback_change` | 回滚本次变更 | `change_id` | 删除本次创建对象/尝试用快照恢复被替换对象；回滚非无损，必须人工核对 |
| `mcp__ovital__export_result` | 导出成果 | `job_id`、`format`（`geojson`/`kml`/`report`/`projected_json`/`gpkg`）、`include_report?` | 导出路径 + SHA256 + 摘要；`gpkg` 需可选 `fiona`，缺失时显式报错，**不要承诺 gpkg 一定可用** |

## 2. 标准流程

### Step 0 读能力（必须先做）

1. 调用 `mcp__ovital__get_capabilities`。
2. 记录并**在后续汇报中保留**：奥维版本、连接状态、VIP/SVIP 探测结果、`simulated`、`verified_against_real_device`、`unverified[]`。
3. 若 `simulated: true`：明确告知用户当前是**模拟服务器**数据，结果只用于流程验证，不是真实奥维操作。
4. 若连接失败：明确报告失败原因（奥维未启动/接口未启用/端口或 PSK 不符/权限不足），不要尝试别的工具“绕过”连接。

**出口条件**：已知道哪些能力可用、哪些未验证；已向用户说明模拟/真实边界。

### Step 1 读出口

1. 若用户已在奥维选中对象：`mcp__ovital__get_selection` → `mcp__ovital__read_object`，取得对象 ID 与原始坐标、坐标语义。
2. 若用户直接给坐标：先确认顺序为 `(lon, lat)`、语义为 CGCS2000（EPSG:4490）；有歧义必须问清楚，不得猜轴序。
3. 报告**原始出口点**；计算后必须同时报告**实际使用的吸附出口**、吸附距离与河道依据。距离超出合理范围、位于支流交汇处或可能跨越山脊时，保留候选并请用户确认，不得默默改点。

**出口条件**：出口点坐标、语义、对象 ID（若有）已确定，并已告知用户“原始点 vs 计算会吸附”。

### Step 2 检查 DEM

1. 调用 `mcp__ovital__inspect_dem`。
2. 逐项检查并在汇报中列出：CRS/投影、分辨率、覆盖范围是否包住完整上游（不能按屏幕范围或预期面积裁断）、NoData 比例与空洞位置、量程异常、DSM/DTM 与高程基准是否未知。
3. 判定数据是否足以支撑本次用途：
   - 覆盖不足/可能截断上游 → 要求更大范围 DEM 或明确标注“截断风险”，不得照常出图；
   - 公开 30m 数据（如 Copernicus GLO-30，DSM）→ 必须说明其分辨率与“非裸地实测”限制，不能承诺小流域工程精度；
   - 无用户 DEM。

**无 DEM 降级策略（必须照做）**：

- 不得假装可计算自然分水岭；不得用影像/水面分割代替 DEM 汇流。
- 若用户仍要草稿：说明只能做“沿等高线/影像的**辅助描绘草稿**”，在汇报中标注“未做 DEM 汇流计算、非工程成果”，并列出待复核部位；草稿不得标记定稿。
- 若奥维地图图片/等高线接口无权限（非 SVIP）：改用本地复核图（若有 DEM）或直接说明无法获取参考图，请用户提供离线影像/等高线数据；不得编造参考图内容。

**出口条件**：数据质量结论明确；若不可用，明确说明并停下等用户决定。

### Step 3 起任务

1. 调用 `mcp__ovital__start_watershed`（DEM 路径 + 出口点/对象 ID + 必要参数），获得 `job_id`。
2. **不要**在一个同步调用里等结果；用 `mcp__ovital__get_job` 轮询（建议间隔 2–5 秒，参考返回的 `job_poll_hint_s`）。
3. 上下文丢失/隔了多轮时，可先用 `mcp__ovital__list_jobs`（辅助工具）找最近的 `job_id`，再用 `get_job` 取状态；`list_jobs` 只是本地任务列表，不替代 `get_job` 的成果与 provenance。
4. 失败或长时间无进展：`mcp__ovital__cancel_job` 后报告；禁止把失败当空数据或成功。

**出口条件**：任务完成且状态为成功；失败已如实报告。

### Step 4 分段复核（必须实际看图）

1. 用 `mcp__ovital__get_job`（`include_images=true`）取得**概览复核图**；再用 `mcp__ovital__review_segment` 对**每一个可疑分段**取局部图（至少覆盖：出口附近、鞍部/平缓分水岭、支流汇入处、DEM 空洞或覆盖边缘）。
2. **必须真的看到图片**：图片应作为 MCP Image 出现在你的上下文中；若工具只返回路径、或返回“图片被拒绝/无法显示”的诊断文本，必须明确说明“未能看图复核”，并据此降低结论可信度，不得声称已复核。
3. 看图时逐项核对并写出依据（不能只写“已检查”）：
   - 分水岭是否落在山脊/山包连线，**没有把影像河谷当山脊**；
   - 是否**跨越鞍部**把邻近流域纳入，或漏掉关键支流/邻近河谷；
   - 出口是否落在正确河道，河网与边界在图上的关系是否合理；
   - 等高线/阴影地形与 DEM 是否一致，差异可能来自配准、植被/建筑、时相还是真实地形；
   - 图上的范围、CRS、像素大小、比例尺、指北针等信息是否完整（缺信息则要求工具补图）。
4. 把疑点按**分段 ID + 位置 + 证据 + 影响**记录；无 DEM 同源等高线时，注明“等高线若与 DEM 同源，不是独立验证”。

**出口条件**：每个关键分段都有“看图结论 + 证据”；未看到图的分段明确标为“未复核”。

### Step 5 疑点与局部修订（v0.1 为参数化重算）

1. 先向用户报告疑点清单与建议，不要直接大改。
2. 需要修订时调用 `mcp__ovital__revise_candidate`，优先使用**分段 ID、锚点、约束**，不要让模型手写长顶点列表。注意 v0.1 的 `anchors_lonlat` **只记录复核锚点并重算参数/报告，不会强行把边界拉过锚点**；不要向用户声称“已按锚点重建边界”。
3. 修订后必须报告：修改前后的面积、影响范围、被修改分段、仍然存疑的部位；保存修改前后边界（工具负责版本化）。
4. **绝对禁止**为了接近目标面积、参考面积或“看起来更顺”而移动边界；修订依据只能是地形/水文证据或用户明确给出的工程约束。

**出口条件**：修订已由证据或用户决定驱动，影响已量化并告知用户。

### Step 6 写草稿

1. 用户确认候选后调用 `mcp__ovital__write_draft`：写入**独立草稿文件夹**（如 `OMAP-MCP 草稿/<任务名>`），带 `idempotency_key`（可自动派生）；工具会写前快照、写后回读。
2. v0.1 只支持**单一无洞多边形**：多部件或带洞边界会被显式拒绝（奥维 `OuterRgnIdx`/区域数语义未实测）。遇到时应回到几何/计算环节处理或请用户确认，**不得**为了能写入而把多部件强行合并、把洞填掉。
3. 失败或超时后**不得直接重写**：先 `mcp__ovital__read_back` 确认对象是否存在；重复创建是缺陷。
3. 不覆盖用户原成果；确需修改已有对象时先说明将要替换的对象并保留快照。

**出口条件**：草稿 `obj_id` 已获得，回读差异已报告（坐标差、面积差、CRS 口径）。

### Step 7 回读

1. 调用 `mcp__ovital__read_back`，比对：回读顶点与本地候选的坐标差、20802 量算与本地点算的面积/周长差。
2. 差异必须先统一口径再解释：坐标语义（CGCS2000 vs GCJ-02）、投影/椭球、单位（20802 周长是 km、面积是 m²）、孔洞与多部件处理。
3. 量算结论必须写清**方法/CRS/单位**；不得把不同口径的两个数字直接比较后宣称“一致”。

**出口条件**：回读差异已量化并解释；无法解释的差异列为疑点。

### Step 8 汇报

向用户汇报（模板见 §6），必须包含：数据来源与 DEM 限制、坐标系统与面积口径、出口吸附情况、分水岭依据、看图复核结论、疑点与未验证项、模拟/真实状态、下一步（定稿或回滚）。不吹能力、不省略警告。

### Step 9 定稿或回滚

1. 定稿：只有用户**显式确认**后才调用 `mcp__ovital__finalize_draft`（必须 `confirm=true`；通过 20112 替换实现，替换语义未在真实设备验证）；定稿后保留版本记录。
2. 回滚：用户要求撤销或发现写入错误时调用 `mcp__ovital__rollback_change`，并报告回滚结果（删除了什么/恢复了什么）；回滚非无损，提示用户人工核对。
3. 导出：按需 `mcp__ovital__export_result`（`geojson`/`kml`/`report`）；GeoPackage 需可选 `fiona`，缺失时应如实说明不可用，不得承诺。导出摘要写明 CRS 与面积口径。

**出口条件**：定稿或回滚已完成并有记录；用户已知晓成果的适用范围与限制。

## 3. 红线（任何情况下不得违反）

1. **不得为凑目标面积修改边界**：目标面积只能作为合理性对照，不能作为优化目标；面积和参考值接近也不代表边界正确。
2. **不得把影像河谷当山脊**：分水岭必须依据地形（DEM/等高线）判断，影像纹理只是辅助。
3. **不得跨鞍部纳入邻近流域**：鞍部、平缓分水岭、支流交汇处必须单独复核并在汇报中标注风险；不确定时保留待复核状态，不得强行定稿。
4. **无 DEM 不得假装已计算自然分水岭**：只能给辅助描绘草稿，必须标注“非工程成果 + 待复核”，且不得定稿。
5. **模拟与真实必须区分**：`simulated: true`、`verified_against_real_device: false` 的结果不得表述为真实奥维/真实设备验证；mock 通过不能代替真实联机验收。
6. **不得伪造精度**：不得承诺米级精度、不得编造坐标/量算数字、不得把“写入成功”“面积接近”“图片好看”当作工程精度证据；精度适用范围必须和数据（DEM 分辨率、DSM/DTM、出口定位）一起说明。
7. **看图复核必须真实发生**：未收到图片或只收到路径时必须如实说明，不得声称已看图；`deepseek-v4-pro` 不支持图片，不能替代视觉模型。
8. **几何修复/简化不得静默改拓扑**：任何简化、去重点、修复自交都必须进入 warnings/报告，并保护出口、鞍部与关键山脊转折点。
9. **不得手写长顶点列表**：优先传候选 ID、分段 ID、锚点 ID；长顶点列表既不可审查也易出错。
10. **凭据与数据安全**：不得把奥维 PSK 写入工具参数、文件、日志或汇报；不得把用户未授权数据上传到外部服务。
11. **写操作必须可回滚**：没有快照、没有幂等键、没有回读确认，不得写奥维；超时不得盲目重发创建。
12. **不确定就报告不确定**：资料缺失（无 DEM/无参考边界/无权限/无 Windows 实机）时，明确列出“未完成/待核验”，而不是用默认值或推测填补。

## 4. 必须检查的疑点清单

| 类别 | 检查点 | 未通过时的处理 |
|---|---|---|
| 出口 | 是否落在正确河道；是否在支流交汇处；吸附距离是否过大 | 报告原始/吸附点与距离，请用户确认或换点重算 |
| 分水岭 | 是否沿山脊；是否跨鞍部；是否漏支流/纳入邻近河谷 | 分段复核图 + 修订/待复核标注 |
| DEM | 覆盖是否完整上游；NoData/空洞；分辨率；DSM/DTM；高程基准 | 补数据/扩大范围，或明确标注截断与限制 |
| 坐标 | 轴序是否 `(lon,lat)`；语义是否 CGCS2000；是否重复偏移 | 停止计算，先核对语义与参考点 |
| 几何 | 闭合、自交、重复点、细长片、多部件、洞 | `validate_geometry` 后报告，非静默修复 |
| 量算 | 面积口径（米制投影）、单位、CRS | 统一口径后再比较；写清方法 |
| 落图 | 写前快照、幂等、写后回读差异 | 按 §2 Step 6/7 处理；异常回滚 |
| 证据 | 模拟/真实、已验证/未验证、图片是否实际收到 | 在最终汇报中逐项声明 |

## 5. 失败与降级矩阵

| 情况 | 允许的动作 | 禁止 |
|---|---|---|
| 无奥维连接 | 用模拟服务器跑流程验证；报告连接失败原因 | 伪称已连接/已写入 |
| 无 DEM | 辅助描绘草稿（标注非工程成果、待复核） | 宣称已做汇流计算 |
| DEM 覆盖不足/NoData 严重 | 报告限制；扩大范围或换数据后重算 | 忽略截断照常出图、定稿 |
| 非 SVIP（无地图图片/等高线） | 用本地 DEM 复核图；请用户提供离线影像 | 编造参考图、把无权限说成能力不足 |
| 模型无法接收图片 | 明确说明无法看图复核；降低结论可信度；改用支持视觉的模型 | 声称已看图 |
| 写入失败/超时 | `read_back` 确认现状，再决定重试或回滚 | 盲目重发创建 |
| 用户要求“凑面积” | 解释不能以面积优化边界；可给证据充分的修订 | 修改边界以贴近目标数值 |
